# auto-pob

Proof of concept: an [egui](https://github.com/emilk/egui) front-end driving Path of Building's
calculation engine headlessly (no PoB window).

```bash
cargo run -p auto-pob --release            # uses the PoB1 install of the main app
cargo run -p auto-pob --release -- <dir>   # or another PoB folder
```

The default folder is `~/.local/share/RustyPathOfBuilding1` on Linux, so run
`rusty-path-of-building poe1` once first. PoE1 only for now.

## Features

- Load a build from a PoB share code or XML, or start a new one; see its key stats.
- Change level and a few configuration options; stats recalculate live.
- Rank unallocated passives by how much they improve a stat (DPS, life, EHP, ...),
  the same way PoB's node power does.
- Passive tree view with PoB's icons and frames, pan/zoom, tooltips, and a heatmap of
  the ranking.

## How it works

| File | Purpose |
|---|---|
| `src/engine/glue/lab.lua` | Tree geometry and node power, on top of `pob.build`. |
| `src/engine/lab.rs` | Handles `LabCommand`s inside the engine thread; decodes sprite sheets. |
| `src/ui/app.rs` | The app shell: startup, build list and build screens. |
| `src/ui/lab.rs` | The Lab tab: tree and node power ranking. |
| `src/ui/tree_view.rs` | Passive tree rendering: camera, arcs, sprites, heatmap. |

## Where PoB's data comes from

We don't maintain game data; we read whatever PoB release the main app installed.
For reference, PoB's data has three sources:

1. **Passive tree** (`TreeData/<version>/`): converted from GGG's official passive tree
   export (JSON + sprite sheets, published per league).
2. **Game data** (`Data/*.lua` marked "automatically generated"): mods, bases, skills,
   gems, etc. Generated by PoB's `Export/` tool from the game's `.dat` files, extracted
   from `Content.ggpk`.
3. **Hand-maintained**: uniques (`Data/Uniques/`), `ModParser.lua` (mod text to
   calculation modifiers) and the calculation modules. This is most of PoB's ongoing work.

Keeping PoB as the source of truth means every PoB update brings new data for free. What
we own is the glue above, which can break if PoB renames or restructures what it calls
(`build.spec.nodes`, `calcsTab:GetMiscCalculator`, the sprite tables, ...).

## After a PoB update

Run the end-to-end engine test against the installed PoB:

```bash
cargo test -p auto-pob --release -- --ignored
```

It loads builds from XML and a share code, changes level and config, ranks nodes, and
checks the tree geometry and sprites. It's ignored by default because CI has no PoB
install.

## Performance (empty build / level 100 build)

- Startup about 3 s; about 500 MB RSS; 0% CPU when idle.
- Tree drawing about 1 ms per frame for the whole tree, less when zoomed in.
- Full recalculation about 30 ms / 110 ms.
- Ranking about 2.5 ms / 6.5 ms per node, so about 10 s for a large build. Parallel
  engines are the planned fix.
